# Evaluation definitions

V1 `evaluate` is frozen for benchmark reproducibility. V2 uses the following explicit definitions. All metrics are descriptive retrospective results, not failure probabilities.

- Partitions and months use `[start, end)`; documented failure intervals use closed endpoints. Each failure belongs to the partition containing its start, even if its end crosses a boundary. Full supplied scored history is used to evaluate that owned event. A caller must retain context before and after partition boundaries.
- Alert episodes are consecutive true five-minute flags. False/missing flags and telemetry gaps greater than five minutes break episodes. Episodes belong to the partition containing their actual onset. `crossing_onset_episodes` counts episodes starting before the partition and still active at its start; these are not counted again as owned episodes.
- `assigned_event_count` includes all onset-owned documented events. `event_count` counts those with at least one nonmissing telemetry bin. Events with none are unobservable and excluded from detection-rate denominator. Partial events have fewer observed bins than the expected five-minute grid within the closed interval; coverage and detection are reported per event. Partial events remain in the observable denominator.
- Detection requires at least one alert flag during the documented event interval. This is overlap, not an early warning. Event detection rate is detected observable events / observable events; undefined denominators produce JSON null.
- Eligible warnings occur in `[failure start - lead_hours, failure start)` and outside **every** documented failure interval. Entire episodes overlapping any other documented failure are excluded from all three warning definitions, including their bins outside that other interval. Earliest-warning lead uses the first eligible positive bin; nearest-warning lead uses the last. Episode-onset warning lead uses the earliest eligible actual episode onset within that window. An episode beginning before the window may have eligible bins but has no qualifying onset. An episode associated with another documented failure has no eligible warning bins or onset. `lead_time_hours` is the earliest-warning alias only.
- An owned alert episode overlapping any documented failure interval is excluded from unannotated episode burden. Unannotated episodes are not proven false positives: annotations are incomplete.
- Observed exposure is the number of nonmissing five-minute telemetry bins times five minutes. Unannotated observed exposure excludes all documented failure intervals. Unannotated alert rate divides owned unannotated episodes by unannotated observed days. Calendar exposure is the elapsed partition duration including outages; the separate calendar rate uses that duration. These denominators are never interchangeable.

`alert_policy` operates causally: it enters after the specified number of consecutive strict high-threshold exceedances. Optional hysteresis retains the alert until a score is at or below the low threshold. Missing scores or thresholds and gaps reset persistence and active state. Without hysteresis, falling below the entry condition resets persistence. Threshold series are aligned by timestamp and must have been estimated without future/test information by the caller.
